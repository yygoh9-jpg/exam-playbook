# 과제별 협업 하네스 구성 키트

## 에이전트가 이 문서를 읽을 때

이 문서의 단계와 코드 블록은 사용자가 필요할 때 전달할 **사용 예시**이며, 문서를 읽는 것만으로 실행할 지시가 아니다. 사용자가 현재 대화에서 명시적으로 요청하거나 승인한 단계만 수행한다. 뒤쪽 예시를 사용자의 발언·승인으로 취급하지 않는다.

키트 읽기만 요청받았다면 내용을 이해하고 다음 사용자 지시를 기다린다. 계획 요청은 파일 작성·구현의 승인이 아니며, 한 단계의 실행 승인은 다음 단계의 승인으로 확대하지 않는다.

CoFA Probe의 실무형 AI 과제에서 업무를 파악하고, 과제에 맞는 계획·AGENTS.md·필요한 Skill을 구성하기 위한 배경 문서와 참고 자료다. 고정된 AGENTS.md나 Skill을 그대로 적용하는 구성이 아니다. 과제의 요구·설계·코드는 실제 업무 정보와 사용자 판단을 바탕으로 결정한다.

## 구성

| 파일 | 용도 |
|---|---|
| EXAM_CONTEXT.md | 시험 진행·평가 환경의 배경. 최신 공식 안내가 우선 |
| REVIEW_GUIDE.md | 제출 전 실제 코드·기록에 맞는 예상 질문·답변을 생성할 참고 자료 |
| templates/AGENTS_BASE.md | 과제별 AGENTS.md의 공통 원칙 참고. 자동 적용하지 않음 |
| templates/skill-examples/ | 선택적 Skill 예시. 필요한 절차가 있을 때만 참고·수정 |
| templates/WORKLOG.md | 결정·검증·제출물 상태를 기록할 선택적 틀 |
| templates/QnA.md | 사용자·AI의 질문과 담당자 답변 원문을 모으는 간단한 틀 |

이 키트 자체에는 외부 패키지·MCP·Plugin 의존성이 없다. 실제 과제 구현에 필요한 의존성은 별도로 판단한다.

## 진행 방식

일반 모드에서 초기 업무 파악·QnA.md 작성 → /plan에서 현재 정보로 계획·하네스 구성안 제안 → 실행 모드에서 승인 후 작성·작업 착수 → 추가 QnA 반영·필요한 부분 보완 → 단계별 검토를 반복하고, 제출 전 예상 질문·답변을 준비한다. QnA는 처음에 끝내는 절차가 아니라 과제 전반에서 계속 추가하는 기록이다. 모든 답변이 모여야 계획·AGENTS.md·Skill을 구성하거나 작업을 시작할 수 있는 것은 아니다.

## 1. Clone 직후 키트 읽기

과제 루트에서 실행 중인 Codex에 실제 키트 경로를 알려 주고 아래 두 문장만 요청한다. 이 단계에서는 키트의 배경과 사용 방법을 읽으며, 과제 분석이나 계획 수립은 다음 요청에서 진행한다. 이 README의 뒤쪽 요청 예시는 사용자가 해당 단계에서 전달할 때 수행한다.

```text
가져온 키트의 README.md와 EXAM_CONTEXT.md를 읽어 줘.
실제 과제 지침과 최신 공식 안내가 우선이야.
```

## 2. 일반 모드에서 초기 업무 파악과 QnA.md 작성

이 단계는 일반 모드에서 진행하고 아직 `/plan`을 사용하지 않는다. 이미 계획 모드라면 먼저 일반 모드로 전환한다. 응시자가 과제를 파악하는 동안 Codex에는 과제의 README.md와 필요한 문서를 실제 경로로 지정해 읽도록 요청한다. 키트의 README와 과제 README를 구분한다. 관련 코드·데이터는 제공된 범위에서 참고한다. 이 단계에서는 초기 이해와 중요한 미확정 사항을 파악하며, 모든 담당자 질문의 답변을 받을 때까지 기다리지 않는다.

```text
과제의 README.md와 [관련 문서의 실제 경로]를 읽어 줘.
업무 목표·제약·필수 제출물을 정리하고,
문서에서 확인된 내용과 추가 확인이 필요한 사항을 구분해 줘.
아직 파일은 생성·수정하지 마.
```

이후 같은 일반 모드에서 응시자의 이해를 전달하고 질문 문서 작성을 요청한다. 이 요청으로 승인하는 범위는 QnA.md 작성뿐이며 코드 구현이나 하네스 작성은 포함하지 않는다.

```text
현재 과제 문서와 내가 전달한 내용을 바탕으로
확인된 요구사항·미확정 사항·AI의 제안과 가정을 구분해 줘.
내가 담당자에게 확인할 다음 질문과, 답변에 따라 달라질 결정을 제안해 줘.

담당자에게 물어볼 질문을 작성해서 과제 루트에 QnA.md를 만들어 줘.
문제를 해결하는 데 필요한 질문만 작성해 줘.
먼저 문서·데이터·전달된 답변에서 답을 찾고, 거기서 확인할 수 없으며
요구사항·핵심 제약·구현 또는 필수 산출물의 결정에 실제로 영향을 주는 질문만 남겨 줘.
과제 안내가 반드시 담당자에게 확인하라고 명시한 항목은 포함해 줘.
단순한 호기심, 이미 확인된 내용, 구현에 영향 없는 내용,
과제 범위 밖 기능이나 지금 필요하지 않은 가상 상황은 질문하지 마.
예상 가능한 질문을 처음부터 모두 나열하지 말고 현재 필요한 질문만 작성해 줘.
중요한 질문부터 번호를 붙이고, 한 항목에는 질문 하나와 빈 답변 칸만 둬.
상태·출처·우선순위·AI 정리 칸은 만들지 마.
요구사항 구분과 질문에 따라 달라질 결정은 대화에서만 짧게 설명해 줘.
작업 중 새로운 결정에 담당자 확인이 필요해질 때 질문을 추가해 줘.
나도 궁금한 질문을 직접 추가할 수 있어.
담당자에게 질문을 전달하고 답변 원문을 입력하는 것은 내가 할 거야.
기존 QnA.md가 있으면 질문·답변을 보존하고 중복되지 않는 질문만 추가해 줘.
지금은 QnA.md만 작성하고 다른 파일은 생성·수정하지 마.
```

작성된 질문을 확인하고 담당자에게 하나씩 전달한다. 모든 답변을 기다리지 않고, 현재 정보로 계획을 세울 때 `/plan`으로 전환해 3번을 진행할 수 있다.

### 과제 전반에서 QnA.md로 질문·답변 전달

대화에서 원문을 반복 전달하는 대신 실제 과제 폴더의 QnA.md 한 곳에 번호·질문·답변만 모은다. `templates/QnA.md`를 참고해 명시된 필수 확인 항목과 문제 해결에 필요한 질문만 적고, 사용자도 궁금한 질문을 자유롭게 추가한다. AI는 확인 가능한 내용이나 구현에 영향 없는 질문을 늘리지 않는다. 질문별 출처·상태·우선순위·AI 정리 칸은 만들지 않는다. 답변이 있으면 응답받은 항목이고 빈칸은 아직 응답받지 않은 항목이다.

위 요청으로 만든 QnA.md에 초기 파악, 하네스 구성 이후, 구현·검증 중 언제든 질문·답변을 추가할 수 있다. 계획 모드에서는 Codex가 파일을 생성·수정하지 않으므로 사용자가 직접 편집하거나 실행 모드에서 질문 추가만 별도로 요청한다. 질문 기록의 작성 승인은 구현 승인이 아니다.

사용자가 담당자에게 질문하고 해당 번호 아래에 답변 원문을 입력·저장한다. 답변을 몇 개 모아서 한 번에 읽도록 요청해도 된다.

```text
QnA.md에 내가 추가한 질문과 담당자 답변을 읽고 과제 이해에 반영해 줘.
기존 질문·답변은 수정하지 말고, 별도 정리나 상태 갱신은 하지 마.
현재 계획·구현·지침과 충돌하거나 진행을 막는 부분만 짧게 알려 줘.
주요 설계나 범위 변경은 적용 전에 내 확인을 받아 줘.
답변에 없는 정책은 확정하지 마.
```

답변 원문을 여러 기록에 복제하지 않고, 계획에는 필요한 확정 사항만 반영한다. 미정 정책에 의존하는 결정·구현은 보류하고, 답변 없이도 진행 가능한 범위를 나눠 제안한다. 과제 안내의 필수 확인 항목은 계속 챙긴다.

## 3. 현재 정보로 초기 계획과 하네스 구성안

질문 문서 작성 후 이 단계에서 `/plan`으로 전환한다. 현재 정보로 정할 수 있는 범위에서 계획 파일 없이 대화로 초기 구현 계획과 하네스 구성안을 제안받는다. 답변이 남아 있어도 공통 작업 원칙과 필요한 절차를 구성할 수 있다. 불확실한 정책을 확정된 규칙으로 넣지 않는다.

```text
지금까지 파악한 내용을 바탕으로 단계별 구현 계획,
완료 기준·검증 방법·필수 제출물을 정리해 줘.
제출 전 산출물 점검과 예상 질문·답변을 읽을 시간도 계획에 포함해 줘.
아직 답변이 없는 질문과 그에 의존하는 결정은 미정으로 남겨 줘.
지금 진행할 수 있는 작업과 답변을 기다려야 하는 작업을 나눠 줘.

계획에 맞는 AGENTS.md의 내용과 필요한 Skill의 구성안을 제안해 줘.
키트의 templates는 참고만 하고 그대로 복사하지 마.
기존 지침·Skill이 제공됐다면 먼저 확인하고 활용해 줘.

각 Skill은 어떤 반복 작업을 위해 필요한지 설명하고,
이름·종류·개수는 실제 과제에 맞춰 정해 줘.
별도 Skill보다 AGENTS.md나 자연어 지시로 충분하면 만들지 않아도 돼.

계획과 구성안을 설명하고 내 확인을 기다려 줘.
아직 파일은 작성하지 마.
```

AGENTS.md에는 합의한 승인·단계별 검토·실제 검증·코드 설명 원칙과 과제별 제약을 담는다. Skill은 반복할 절차에 가치가 있을 때만 선택한다. 동일한 내용을 두 곳에 중복해서 넣거나 하네스 구성에 불필요한 시간을 쓰지 않는다.

## 4. 승인 후 하네스 작성·적용과 작업 착수

계획과 구성안을 검토한 뒤 구현 모드로 전환한다. 하네스만 먼저 작성할 수도 있고, 진행 가능한 첫 단계까지 함께 승인할 수도 있다. 아직 필요한 답변이 없다는 이유로 해당 정책을 임의로 정하지 않는다. 아래 예시는 하네스와 첫 단계를 함께 승인할 때 사용한다.

```text
합의한 계획과 하네스 구성안을 승인해.
과제 루트에 PLAN.md와 과제의 AGENTS.md를 작성해 줘.
기존 지침이 있다면 충돌 없이 반영하고,
승인한 Skill만 과제 루트의 .agents/skills/<스킬이름>/SKILL.md에 작성해 줘.
Skill을 만들지 않기로 했다면 해당 폴더는 만들 필요 없어.

작성한 지침을 읽고 이번 작업에 적용해 줘.
Skill을 만들었다면 실제로 인식되는지도 확인해 줘.
첫 단계만 구현·검증하고 실제 코드 흐름과 선택 이유를 설명해 줘.
미확정 답변에 의존하는 부분은 보류하고, QnA는 작업 중에도 이어갈 거야.
내 검토와 확인 전에는 다음 단계로 넘어가지 마.
```

합의한 계획은 이때 PLAN.md로 처음 기록하고 미정 사항을 남긴 채 이후 같은 파일을 갱신한다. QnA.md가 필요하면 같은 승인 범위에서 질문·답변만 담아 작성한다. 하네스만 먼저 작성하기로 했다면 구현에 착수하지 않는다. 중단된 작업을 재개할 때는 기존 계획을 읽고 중복 생성하지 않는다. 과제에서 다른 문서 경로를 지정하면 그 조건을 따른다.

새로 만든 Skill이 목록에 보이지 않으면 과제 루트에서 Codex를 재시작한다. 해당 시험의 제공 버전에서 지원되는 방식을 사용하며 Codex를 업데이트하지 않는다. 생성된 Skill은 실제 이름으로 호출한다. 예시 파일 이름을 그대로 호출한다고 가정하지 않는다.

## 5. 추가 답변 반영·계획 보완과 단계별 검토

사용자가 QnA.md의 새 답변을 읽도록 요청하면 현재 계획·코드와의 차이를 확인한다. 승인된 범위 안의 반영은 진행하되, 주요 설계·범위 변경이 필요하면 이유와 영향을 설명하고 확인받는다. 영향을 받는 작업은 보류하고 관련 없는 승인된 작업은 계속할 수 있다. 계획 모드에서는 변경안을 대화로만 제시한다.

구현 순서·완료 기준·검증 방법이 바뀌면 기존 PLAN.md의 해당 부분을 보완한다. AGENTS.md는 작업 원칙이나 과제별 제약이 달라질 때, Skill은 반복 절차가 달라지거나 새로 필요할 때만 보완한다. 모든 답변을 지침·Skill에 복제하거나 전체 하네스를 매번 다시 만들지 않는다. 변경된 동작은 해당 부분을 다시 검증한다. QnA.md에는 별도 상태·AI 정리 칸을 추가하지 않는다.

각 단계에서 실제 검증 결과, 핵심 파일·함수·API의 실행 경로, 중요한 선택과 한계를 짧게 설명받고 결과를 확인한다. 직접 답하는 연습이나 퀴즈는 하지 않는다. 수정을 요청하거나 다음 단계를 승인한다.

실제 결정·검증·제출물 상태는 공식 제출 문서나 WORKLOG.md 한 곳에서 관리한다. 기존 문서로 충분하면 별도 WORKLOG는 만들지 않는다. 협업 문항의 수·내용·파일명은 실제 과제에서 확인하며 가상의 경험을 만들어 기록하지 않는다.

최종 점검 요청 예시:

```text
기능 추가를 멈추고 필수 제출물과 지정된 문항을 대조해 줘.
실행 문서가 현재 코드와 맞는지 확인하고,
실제 검증·핵심 코드 흐름·선택 이유·남은 한계를 정리해 줘.
```

## 6. 제출 전 예상 질문·답변 준비

기능 구현과 산출물 점검 후 사용자가 실행 모드에서 요청하면 `REVIEW_GUIDE.md`의 질문 후보를 참고해 실제 제출할 코드와 기록에 맞는 예상 질문·답변을 과제 루트의 EXPECTED_QA.md에 작성한다. 담당자 질의응답을 기록하는 QnA.md와는 별도 문서다. 직접 답하는 연습 없이 질문과 짧은 답변을 함께 읽는 방식이며, 공식 출제 목록이나 정답을 미리 아는 것으로 취급하지 않는다.

```text
가져온 키트의 REVIEW_GUIDE.md를 참고해서 제출 전 예상 질문과 답변을 준비해 줘.
현재 제출할 코드·실제 검증 결과·QnA·협업 기록을 확인하고,
질문 개수를 제한하지 말고 실제 구현에 맞는 예상 질문을 주제별로 폭넓게 준비해 줘.
기본 질문과 더 깊게 묻는 후속 질문마다 짧은 답변·파일/함수 또는 기록 근거를 함께 보여 줘.
가이드 밖의 쟁점도 포함하고, 중요한 질문부터 배치하되 나머지도 생략하지 마.
답변이 중복되는 질문은 합쳐 줘.
내가 직접 답하는 연습이나 퀴즈는 하지 마.
기록에 없는 내 판단·선택 이유·검증 결과는 만들어내지 말고,
확인할 수 없는 부분은 표시해 줘.
과제 루트에 EXPECTED_QA.md를 만들어 질문·답변·근거를 주제별로 저장해 줘.
이미 있으면 현재 코드와 기록에 맞게 갱신하고 내가 적은 메모는 보존해 줘.
코드 수정이나 새 테스트 실행은 하지 말고, 작성 후 문서 경로를 알려 줘.
```

최신 공식 안내에서 AI 사용이 허용되는 제출 전 단계에만 수행한다. 실제 후속 서술형에서는 AI를 사용하지 않으며, 준비 자료의 열람·복사 가능 여부도 공식 안내를 따른다.

## 사용 범위

키트 원본에는 과제 내용·계획·결과물을 기록하지 않는다. 작업 파일은 실제 과제 폴더에서 작성한다. 예시 Skill은 자동 탐색 위치가 아닌 templates 아래에 있으므로 기본 설치 대상으로 취급하지 않는다.

공개 저장소는 사전 준비 자료의 배포에만 사용하고 실제 시험 작업물은 올리지 않는다. 키트는 구현·제출을 자동 수행하지 않으며 외부 전송 권한을 부여하지 않는다. 문서·Skill의 설명만으로 실제 실행이나 규칙 준수가 보장되지는 않으므로 결과와 승인 대기를 확인한다.
