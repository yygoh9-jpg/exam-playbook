# 한 단계의 구현과 검토

이 파일은 과제별 Skill을 설계할 때 참고할 선택적 예시다. 이 이름과 절차의 설치·사용은 필수가 아니다. 실제 과제의 반복 작업과 검증 필요에 맞춰 선택·수정한다.

과제 지침, 프로젝트 지침, 현재 계획과 이전 검토 결과를 읽고 지금 승인된 단계의 범위를 확인한다. 승인이 불명확하면 변경 전에 확인한다.

## 구현·검증

- 현재 단계의 목표와 완료 기준을 기준으로 구현한다. 범위 안 테스트·오류 수정은 계속하되, 요구나 주요 설계를 바꿔야 하면 이유와 대안을 먼저 확인받는다.
- 구현 중에도 QnA가 추가될 수 있다. 사용자가 새 답변을 읽도록 요청하면 영향받는 코드·계획·검증을 확인한다. 주요 변경은 승인 후 반영하고, 결정이 필요한 관련 부분만 보류한다. 작업 원칙·반복 절차가 바뀌지 않으면 AGENTS.md·Skill을 다시 만들지 않는다. QnA 원문은 보존하고 상태·AI 정리 칸은 추가하지 않는다.
- 기존 테스트와 변경 위험에 맞는 정상·경계·예외 사례를 실제 실행한다. 업무 계산은 독립 기대값으로 대조한다. 실행 불가·실패·통과를 구분한다.
- 웹서비스면 해당 단계의 데이터·API·화면 연결을 확인한다. 사용자 직접 화면 확인이 필요하면 조작 순서와 기대 결과를 안내하고 미확인 상태를 남긴다. 자동 GUI 조작은 사용하지 않는다.

## 단계 종료 보고

필요한 정보만 간결하게 전달한다.

1. 무엇이 구현됐고 완료 기준을 충족했는가? 실제 실행 명령·결과와 실패·미검증은 무엇인가?
2. 핵심 사용자 행동 하나가 실제 어떤 파일·함수·API를 거쳐 실행되는가? 해당하는 입력·권한 검사·핵심 로직·저장·응답·화면 갱신 및 주요 실패 경로를 연결한다. 없는 계층을 만들어 설명하지 않는다.
3. 중요한 알고리즘·설계 선택은 어떤 목표·제약을 위한 것인가? 실제 검토한 대안과 절충, 검증 근거·한계는 무엇인가? 입증하지 않은 최적성을 주장하지 않는다.
4. 실제 AI 제안 중 사용자가 수용·수정·보류한 내용과 이유가 있다면 무엇인가? 사용자가 하지 않은 결정을 꾸며내지 않는다.
5. 직접 답하는 연습이나 퀴즈는 하지 않는다. 사용자가 제출 전 준비를 요청하면 키트의 REVIEW_GUIDE.md를 실제 경로로 확인하고, 현재 코드와 실제 기록에 맞는 예상 질문·짧은 답변·근거를 함께 제시한다. 기록에 없는 사용자 판단이나 검증 결과는 만들지 않는다. 해당 자료가 없으면 현재 코드와 기록을 기준으로 준비한다.

다음 단계 범위와 미해결 사항을 알리고 사용자의 확인을 기다린다. 전체 계획이 승인됐어도 합의한 단계별 검토를 건너뛰지 않는다.

## 기록과 제출

현재 승인 범위에서 기존 계획의 상태와 공식 제출 문서 또는 WORKLOG를 갱신한다. 결정·검증·핵심 실행 경로·필수 제출물의 상태를 짧게 유지하며 동일 내용을 여러 문서에 복제하지 않는다.

최종 단계에서는 실행법이 현재 코드와 일치하는지, 지정된 모든 제출 파일과 문항이 충족되는지 대조한다. 과제 수행 중 AI 협업 답변 문서는 허용 범위에서 실제 기록을 근거로 작성할 수 있으나, 제출 후 AI 금지인 서술형 답안을 대신 작성하지 않는다.
