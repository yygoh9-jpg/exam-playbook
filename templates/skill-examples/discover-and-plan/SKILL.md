# 업무 발견과 계획

이 파일은 과제별 Skill을 설계할 때 참고할 선택적 예시다. 이 이름과 절차의 설치·사용은 필수가 아니다. 실제 과제에서 재사용 가치가 있는 절차인지 판단하고, 필요한 경우에만 내용을 조정해 구성안을 제안한다.

현재 과제 지침, 사용자 설명, 제공된 자료와 담당자 답변을 기준으로 진행한다. 자료가 없으면 있다고 가정하지 않는다.

## 정보가 부족할 때

- 사용자·업무 흐름·목표를 짧게 요약하고 확인된 사실, 미확정 사항, 제안 가정을 구분한다.
- 문서·데이터·기존 답변에서 먼저 답을 찾고, 그곳에서 확인할 수 없으며 문제 해결의 결정에 실제로 필요한 질문만 작성한다. 명시된 필수 확인 항목은 포함하되 단순 호기심·중복·과제 밖 기능·현재 불필요한 가상 상황은 제외한다. 미래 질문을 미리 모두 쌓지 않고 작업 중 필요해질 때 추가한다. 담당자가 한 번에 하나만 답하면 한 항목에 질문 하나만 담는다. QnA.md에는 질문·답변만 모으고 사용자 질문과 원문을 보존하며 상태·AI 정리 칸은 만들지 않는다.
- 초기 분석과 QnA.md 작성은 일반 모드에서 사용자의 요청 범위에 따라 수행한다. /plan은 계획·하네스 구성안을 제안할 때 사용한다. 이미 계획 모드라면 파일을 작성하지 않고 일반 모드로 전환해야 함을 알린다.
- 담당자와의 대화는 사용자가 수행한다. 전달받은 답변을 반영하고 필요할 때 후속 질문을 좁힌다. 모든 질문이 끝나야 한다고 가정하지 말고, 진행 가능한 범위와 막힌 결정을 나눈다.

## 계획을 제안할 때

- 사용자가 이해한 문제를 확인하고 필수·선택·제외 범위를 제안한다. 데이터 의미·목표·제약을 임의로 확정하지 않는다.
- 핵심 사용자 흐름, 필요한 데이터와 연결, 중요한 기술 선택·대안·절충을 정리한다. 규모에 맞는 검토 가능한 단계로 나누고 각 단계의 결과·완료 기준·검증 방법을 제시한다.
- 실제 과제에서 요구한 제출물의 정확한 파일명·경로·내용·문항을 추적한다. 제시되지 않은 문항이나 제출 파일을 공식 필수 조건으로 만들지 않는다.
- 기존 AGENTS.md·Skill이 있으면 읽고 활용한다. 필요한 과제별 보완안만 제시한다. 별도 Skill이 필요하지 않으면 추가하지 않는다.
- 답변이 남아 있어도 현재 정보로 초기 계획과 하네스 구성안을 제안한다. 미정 사항에 의존하는 작업과 지금 진행 가능한 작업을 구분하며, 확인되지 않은 정책을 지침으로 확정하지 않는다.
- 계획과 구성안을 보여주고 사용자의 확인을 기다린다. 계획 모드에서는 파일 생성·수정 없이 대화로 제안한다.

## 진행 중 새 답변을 반영할 때

사용자가 새 답변을 읽도록 요청하면 현재 계획·코드와의 차이를 확인한다. 달라지는 결정과 관련 작업만 짚고 주요 설계·범위 변경은 확인받는다. PLAN.md는 바뀐 계획, AGENTS.md는 바뀐 작업 원칙·제약, Skill은 바뀐 반복 절차가 있을 때만 보완안을 제안한다. 전체 하네스를 다시 만들거나 매 답변마다 QnA 요약을 기록하지 않는다. 답변과 무관한 승인된 작업까지 일괄 중단하지 않는다.

## 승인 후 기록

처음 계획을 수립할 때는 기존 계획 파일을 전제하지 않는다. 사용자가 파일 작성을 승인하고 실행 모드가 된 뒤 합의한 단계·완료 조건·검증 방법을 과제 루트의 PLAN.md에 작성한다. 이후 같은 파일을 갱신하며 단계 승인과 가정의 상태를 구분한다. 작업 재개 시에는 이미 작성된 계획을 먼저 읽고 중복 생성하지 않는다. 과제에서 다른 계획 문서 경로를 지정했다면 그 경로를 따른다.

실제 결정·검증·산출물 상태는 기존 공식 제출 문서나 WORKLOG.md 중 한 곳에서 관리한다. WORKLOG 틀이 필요하면 키트의 templates/WORKLOG.md를 참고하되 현재 환경의 실제 경로를 확인한다. 계획 수립만으로 구현·전체 단계 실행을 승인받았다고 해석하지 않는다.
