# 과제별 AGENTS.md 작성 참고

이 문서는 자동 적용할 지침이 아니라 과제별 AGENTS.md의 구성안을 작성할 때 참고하는 예시다. 확인된 과제의 범위·기술·실행 방법·검증 조건에 맞게 필요한 내용을 선택·수정하고, 사용자 승인 후 과제 루트에 작성한다.

## 공통 원칙 후보

- 실제 과제 지침과 최신 운영 안내를 우선한다. 자료·기존 코드의 존재를 가정하지 않는다. 확인된 요구사항, 사용자가 승인한 결정, AI의 제안·가정을 구분한다.
- 업무 담당자 질문은 문서·데이터·기존 답변에서 확인할 수 없고 문제 해결의 결정에 실제로 필요한 것만 제안한다. 명시된 필수 확인 항목은 포함하되 단순 호기심·중복·과제 밖 질문은 제외한다. 후속 질문은 작업 중 필요해질 때 추가한다. 사용자가 전달한 답변을 반영하며, 답하지 않은 내용을 확인 사실로 만들지 않는다.
- QnA는 계획·하네스 구성 이후와 구현 중에도 계속될 수 있다. 현재 정보로 계획·지침을 구성하고, 미정 정책에 의존하는 부분만 보류한다. 사용자가 새 답변을 읽도록 요청하면 영향을 받는 계획·코드·지침만 보완하며 주요 변경은 확인받는다. QnA.md를 쓰는 경우 사용자 질문과 답변 원문을 보존하고 상태·AI 정리 칸은 만들지 않는다.
- 구현 전 계획·단계별 완료 기준·검증 방법·필수 산출물을 제안하고 확인받는다. 기존 계획 파일이 있으면 이어서 활용한다. 계획 모드에서는 파일을 작성하지 않는다.
- 사용자 승인 후 파일을 변경한다. 승인된 현재 단계 안에서는 구현·테스트·오류 수정을 진행하고, 단계가 끝나면 결과와 검증·코드 설명을 제시한 뒤 다음 단계 승인을 기다린다. 범위나 주요 설계 변경도 먼저 확인받는다.
- 과제별 기술·실행 제약은 파악한 뒤 이 문서에 필요한 만큼 반영한다. 하네스 재설계·Skill 추가를 기본 작업으로 반복하지 않는다.
- 단계 검토에서 실제 파일·함수·API에 근거한 핵심 실행 경로, 선택 이유와 한계를 짧게 설명한다. 직접 답하는 연습이나 퀴즈는 하지 않는다. 제출 전 요청받으면 실제 코드와 협업·검증 기록에 근거한 예상 질문·짧은 답변·근거를 함께 제시한다. 기록에 없는 사용자 판단이나 검증 결과를 만들지 않는다.
- 실제 실행 근거로 통과·실패·미검증을 구분한다. 사용자 화면 확인과 AI의 테스트를 구분하고, 구현한 함수를 정답 계산기로 재사용하지 않는다.
- 필수 산출물은 정확한 파일명·위치·문항·완료 조건으로 추적한다. AI 협업 문서는 실제 제안·사용자 판단·실행 기록에 근거하며 경험을 꾸며내지 않는다.
- 기록은 기존 제출 문서를 우선 활용하고 중복 파일을 늘리지 않는다. 실제 후속 서술형 단계에서는 AI 도움을 제공하지 않는다. 외부 전송·게시와 도구 사용은 승인 및 시험 규칙 범위 안에서만 수행한다.
